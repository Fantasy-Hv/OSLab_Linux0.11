# 实验6-内存映射实验

### 一、多进程内存使用

使用内存，就是让程序加载进内存然后执行。

因为内存中要执行多种程序，同时要保证系统运行的安全性，不能直接按照应用程序指定的地址直接访问物理内存。

用户程序可见和直接使用的内存地址称为逻辑地址，是程序内部的相对地址。

物理地址是发送到总线上并最终到达内存控制器的地址。

为了协调程序代码内存地址的相对性和物理内存访问的绝对性，需要对程序使用的地址进行重定位。

重定位按照其执行的时机可分为编译时重定位、载入时重定位和运行时重定位。这里考虑运行时重定位。

实现重定位的总思想是采用 程序物理基地址+偏移量 的计算方式将逻辑地址转换为物理地址，其中程序的物理基地址在载入内存时可知，偏移量由程序的逻辑地址给出。可以将程序的物理内存基地址存储在其pcb中并需要在运行时缓存到寄存器以供硬件进行内存映射。

### 二、程序分段

考虑一个程序内部的内存使用，一个程序使用到的内存可以根据存储的数据对象分为各种不同功能的段区域，如代码段、数据段、函数库段、栈、堆。并且程序使用的地址也是相对于段的偏移，而不是整个程序内的偏移，为此需要给每个段分配一个基地址。

处于安全和方便管理的考虑，可以将内存基地址对应的粒度变细，从一个基地址对应一个进程改为一个基地址对应进程的一个段，因为一个进程有多个段，故也有多个基地址，所以需要一个段表来描述各个段的基地址以及其他信息，因为这些段都是属于一个进程的，故而每个进程都会有自己的段表，称为该进程的LDT。

### 三、内存分页

如果为每个段直接分配对应的连续内存分区，那么随着系统的运行，内存中会产生很多碎片，并且可能出现明明内存空闲总量足够却因不连续而无法分配给新的段的问题。

因此将内存分一个个为大小固定的块，称为页，当为一个段分配内存时，不是分配一整块大空间，而是将段拆成若干页进行分配。这样就避免了内存浪费的问题。

使用页表这一数据结构来描述内存页。一个页表项包含了程序的逻辑页和物理页的映射。

### 四、段页结合

使用虚拟内存这一抽象来将分段和分页结合起来。为每个进程提供一个完整地址空间的抽象，好像它在独占整个系统内存。将虚拟地址也进行分页。用户程序直接使用的是虚拟内存中的逻辑地址，即段和段内偏移。

操作系统设置好ldt和页表，并将起始地址放在对应寄存器中（ldtr、cr3）

在用户程序实际访问内存时，由硬件根据逻辑地址和段表计算出对应于虚拟内存中的线性地址（虚拟地址 ， 段基址+段内偏移），然后再根据页表将线性地址映射为物理地址，具体来说，32位的线性地址，高10位是页目录号，中间10位是页号 ，低12位是页内偏移。通过查找页表将高20位的虚拟内存的页替换成实际的物理页框号，然后和页内偏移拼接起来，送往总线。

每个进程都有各自的虚拟内存抽象，因此需要为每个进程维护一个页表，用pcb的一个字段指向它。进程切换时需要同时切换段表和页表。

### 五、实验内容

##### 内存映射追踪

使用bochs汇编级调试，在linux0.11中执行一个c程序，其中有一个永不主动结束的while循环，通过跟踪内存数据修改程序的变量，使循环终止。单独c语言指针的值是段内偏移，完整的逻辑地址是段选择子：段内偏移，在本次实验中，是 ds：xxx。整个地址重定位的过程是：GDT表存储了每个进程LDT所在段的物理内存基址（GDT是描述LDT所在段的段表，通过GDT，就可以访问LDT），ldtr寄存器存储了当前进程的LDT表所处段在GDT对应中的描述符索引，即 GDT[ldtr] => LDT基址，然后ds寄存器存有段描述符在ldt中的索引，通过ds可在ldt中找到对应内存段的段描述符从而得到段的虚拟基地址，然后将段的虚拟基地址加上段内偏移就得到了线性地址。一个线性地址由10位页目录号+10位页号+12位页内偏移组成。通过cr3寄存器得到页目录表的物理基址，每个页目录项和页表项都是32位（4字节）大小，cr3+页目录号* 4就得到了二级页表的物理基地址，页表基地址+页号*4 就得到了对应页表项的物理内存地址，该表项的前20位即物理页框号，物理页框号+页内偏移就得到了真实的物理地址。至此，由c语言指针到物理内存地址的翻译就结束了。

##### 实现共享内存

在linux0.11上实现内存共享,并将实验5中使用的文件缓冲区改成内存缓冲区,并将生产者和消费者作为两个独立程序分别运行。可以通过将进程的逻辑地址映射到同一块物理页框来实现内存共享。
![img](imgs\sham.png)
在linux0.11中，所有进程共享同一块虚拟内存，每个进程使用虚拟内存中的64MB空间，进程号*64MB即是进程的段基址, 并且进程的代码段和数据段的基址是相同的，整个系统中只有一个页表。为了实现内存共享，本次实验需要为用户程序 提供 `shmget()`和 `shmat()` 系统调用,只需要支持生产者消费者运行即可。

```c
//根据键值 key获取或创建一个共享可读写的内存段，并返回其标识符（shmid）
int shmget(key_t key, size_t size); 
	//size：共享内存段的大小（字节）。如果是获取已存在的段，可以设为 0。

//将 shmid对应的共享内存段附加到调用进程的地址空间，并返回映射的起始（逻辑）地址。
void *shmat(int shmid, const void * shmaddr, int shmflg);
	// shmaddr：期望的映射地址（通常设为 NULL，由系统自动选择）

```
